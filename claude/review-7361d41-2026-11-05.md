## Findings

1. **Medium — the result window can be saved twice.**
   - `openOutcomeDialogForRecord` now opens with the list record (good).
   - If Karl presses Save while `fetchOutreachRecord` is still running, `saveOutreachOutcome` disables the window. When the full record then arrives, `openOutcomeDialog(fullRecord, true)` calls `setOutcomeDialogEditing(true)`, which re-enables Save while the first save is still in flight.
   - A second click logs the outcome twice: two Activity rows and a double status change.
   - **Fix:** keep a `outcomeSaveInProgress` flag. While it's set, the late record only replaces `selectedOutreachRecord` and changes nothing on screen. Add a test, or at least an assertion that the flag is checked.

2. **Medium — `ensureHeaderColumns_` now reads row 1 of the sheet on every call.**
   - It has 32 call sites. Several are on hot paths: Activity Log appends on every send (~6824/6832), outcome saves (~7243), count saves (~1349) and account writes.
   - That's an extra Sheets read per request on an app whose main complaint is time-outs.
   - The duplicate can only happen when the cached map says a column is **missing**. **Fix:** keep the cache fast path. If the cached map already has every requested column, return it with no read. Only when something looks missing, read the live header row before appending (the new code), then refresh the cache.

3. **Low/medium — `isDoNotContact_` was widened beyond Closed.**
   - It now also returns true for outcome Unsubscribed, Not interested or Do not contact, regardless of status.
   - That changes three things: `isDueOutreach_` (the Due today queue), `isReadyOutreach_`, and the follow-up tasks sent to the weekly task manager (~10801).
   - Example: a business whose old outcome is "Not interested" but whose status was later set to "Interested" or "Existing customer" would silently drop out of those lists.
   - Phase 1 only asked for Closed. **Fix:** add only `"closed"` to the status and outcome checks. If the wider rule is intended, say why in the header and add a test for the status-changed-later case.

4. **Missing — A7 cleanup step for Karl.**
   - The guard is in, but the request also asked for a safe one-time step to remove the existing empty duplicates. Checked read-only on the live sheet, 2026-11-05:
     - **Outreach Campaigns:** column **U** "Schedule Detail" is empty; **V** holds the data.
     - **Outreach Campaign Recipients:** column **Y** "Message Stage" is empty below the header; **Z** holds the data.
   - **Fix:** add to PROJECT_STATUS (setup steps): delete column U of Outreach Campaigns and column Y of Outreach Campaign Recipients, **only when no campaign is Scheduled or Sending**. Reason: the batch writes whole rows sized to the current column count, so a column deleted mid-run shifts that write.
